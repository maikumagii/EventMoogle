Getting started

When the bot is added, it posts a short welcome in the server’s system channel. Commands appear as they become useful: the event commands once there’s an announcement channel, /whoami once there’s something to pick. New to the bot? Run /setup (needs Manage Server). It starts by explaining how the bot works (it reads your Discord events, picks a preset by keywords in each event's name, uses that preset's party composition, then fills the slots by matchmaking signups), then walks through where events are posted, roles, categories and presets, in that order. Continue later keeps your place, including after a timeout or restart; /setup stays until you press Finish on the last step. The website has the same walkthrough, with the settings on each step and a step about the server’s own pages: an admin opening a server that isn’t set up lands on it, and until it’s finished every admin’s Home and the server’s Home say so. Your place is shared, so you can start in Discord and finish on the website, or the other way round; finishing either finishes both. /about-new-features shows Event Moogle’s feature showcases, the same ones as the Inbox, to everyone.

If you remove one, the features that need it stop, and Settings → Server → Status (or /settings) says what’s missing. Permissions marked optional only matter if you use that feature.

Purchases and the free week

In Settings → Server → Subscription, buy 3 or 12 months of Paid without renewal when purchases are available, even while subscribed or comped. These give 90 or 365 days. Discord shows the price and handles checkout; the bot never sees card details. Buying more adds time; prepaid time waits while a subscription or operator comp gives this server Paid, and runs while it has Plus. An Inbox notice arrives a week before expiry. Unused event passes never expire and stay available while the server is Paid. An eligible server can Start free week once (Plus and gifted days do not use it up; a past Paid subscription, operator Paid comp, bought months or free week does); its Inbox reminder arrives two days before expiry. Expiry deletes nothing.

An Event pass in an event’s Manage panel gives that date Paid’s event features, including one invite code, unlimited crossposts and replacement searches, automatic presets, attendance, characters and delayed signup. Server limits, automatic category roles, private static channels, audit and Visitors still follow the server’s plan. A repeating event needs a pass for each date. Paid servers do not need event passes; Free and Plus servers can use them. Each purchase applies once, and a used pass cannot be moved to another date.

Any member can choose /help → Free and Paid → Gift Paid, choose a server they share with the bot, and give months of Paid. Choose anonymity before selecting the receiving server to hide your name from its admins. Purchases not applied immediately stay available: open Subscription to use months here, or Manage on the intended date for an event pass.

Credits for your server

Credits are gifts held by a person, not a server balance or a purchase. An operator-given event pass credit never expires while unused. Its holder can spend it where they organize, on a live event’s current date, through Manage → Event pass → Use my event pass credit. Subscription shows their unused credit too. Only the holder can use it; a Paid server or an already covered event needs none. A bought pass and a credit remain separate choices. Coverage is the same as a bought event pass above and ends with that date, not the whole repeating series.

Bot profile (Paid)

In Settings → Server → Bot profile, choose Edit bot profile to change the bot’s name, avatar, banner and bio here. Names allow 32 characters, bios 190. Upload PNG, JPEG, GIF or WebP images under 10 MB; banners need at least 680 × 240 pixels. Leave an upload blank to keep its image. The bot needs Change Nickname to set its name.

Server address (Paid)

In Settings → Server → Server address on the website, claim a name for the server’s pages, so /s/lanternfall works as well as the server’s number. Names use 3 to 32 letters, numbers and single hyphens, with at least one letter. Each name belongs to one server, first come, first served; change it or give it up there at any time. If Paid ends, the server keeps its name for a week. After a week without Paid, the name is released and any Paid server can take it.

Reset returns all four fields to Discord’s defaults. When Paid ends, the bot does this once automatically. Your saved name and bio remain available to restore when Paid returns; upload images again, since the bot never keeps them. These changes are audited.

Support EventMoogle in Subscription or /help → Free and Paid offers optional tips. Tips add no features. The buyer receives a private thank-you; Subscription acknowledges support without names, amounts or a list of supporters. Open DMs from the bot to receive the thank-you.

Access & Safety has a dropdown for Settings Access, Safety, Admin Channel and Audit Log. Inbox stays available in the footer throughout. Run Setup Again starts at the first step.

Inbox and Status

Open Server → Status to see missing permissions, unavailable channels and presets that need attention. The Inbox stays in the settings footer, with one item for each affected preset. Marking an item read does not approve a role or fix its cause. If the admin channel is set, one alert lists the presets affected by a change; retries and recovery do not ping.

If an event thread is locked, archived or inaccessible, saved settings and the roster still update. The bot waits for access to post the latest roster rather than opening the thread just for a settings edit. Restore access or unlock it as Status asks. Independently due event reminders still follow their normal rules.

An old preset-update offer may still have buttons. They no longer change the event: updates are automatic. Open Manage to see or change the current roster.

Characters and Open slot roles

Characters are Paid; members manage up to 24 per server with /character. In Settings → Events → General Settings, Characters on events starts at As many as you want. Choose Only Myself to turn characters off. There is no event cap beyond saved characters unless the host sets a character default or event rule. The host’s plan and switch apply to allied members too. Setting changes are audited.

Without Paid or an event pass, or with Characters on events: Only Myself, active character signups read as Myself (all roles) and extra lines collapse into that line, without pings. Characters, their roles and their roster names are ignored. Nothing is deleted; restoring Paid and As many as you want before the event restores lines in their original order. Ended events keep recorded names. Leave and Manage can remove hidden lines. Attendance stays per line, with one member outcome per event.

What roles are in an Open slot? is Free, server-wide and empty by default. Pick the server’s self-assigned role groups; their current roles are offered. The list has pages when needed. Join and Change role offer them whenever the event has any Open slot, even if all places are occupied. A chosen role in an Open slot shows BRD (Open); named and flex slots keep their usual rules. Roles deleted or no longer self-assigned stop being offered. With no self-assigned roles, add them under Roles → Self-assignable roles first.

Static cards and channels

Choose a static in /settings → Statics. The Static settings dropdown offers Members, Welcome message…, Name and purpose…, Leader and card and Dissolve…. Use Name and purpose to rename the static or change which events it is for; signup restrictions still come from the preset’s Static. Leader and card chooses who leads it and where its card goes. A blank welcome restores the default. Cards show the welcome below their members and never ping on edits. Pinning needs Pin Messages: Status reports a refused pin, including Discord’s pin limit, without removing any other pin.

On Paid, Create static… can also create private text and voice channels when Role management is on and the bot can Manage Channels. Members ask an admin to create a static; existing statics and their leaders keep working. Choose a Statics category, or clear the picker for top level. A static without channels gets them from Static settings → Create private channels. The static’s role and the bot have access; admins see them through Administrator. Dissolve… keeps channels by default and asks before deleting their history. Channel creation, renaming, deletion and category changes are recorded in the Paid audit log. See Private text and voice channels for plan lapses and deleted channels.

Safety

  • Elevated roles: a self-assignable role (or ping role) that grants permissions @everyone doesn’t have is offered to members only after you confirm it: Review elevated roles shows each one with the permissions it would give, to Confirm or Skip. If its permissions change later, it stops being offered until you review it again. Roles with Administrator are never offered.
  • Blocking: block members from giving themselves roles, or from signing up for events (organizers can still add them; anyone can always leave), or choose a blocking role. The two member pickers show existing blocks; selecting or unselecting members saves immediately. Unchecking removes only that restriction, preserving their other restriction and members on other pages. Full pages offer another page for additions.
  • Members who change roles, or press Join/Leave, too fast are paused for 10 minutes.

Admin channel

Where security alerts are posted, on every plan (the bot checks it can post there; Send test message confirms it): spam pauses, blocked members trying anyway, elevated roles confirmed or changed, and privacy requests that hide someone’s admin actions. Problems that stop a preset or event working are posted there too: one message per change, listing every preset it affected, mentioning the person who made the change once (only when the bot knows for certain who it was). A problem that comes back is posted without a mention, and ✅ Resolved notices never ping. On Paid, you can also copy chosen audit log groups there. Keep it private to admins.

Settings access

Who can use /settings and /setup: members with Manage Server (the default), the server owner only, or the owner and roles you choose. Only the owner can change this. The roles picker appears only when the owner-and-chosen-roles option is selected. Organizers keep their event tools whatever it says. Discord also controls who sees /settings in Server Settings → Integrations.

Audit log (Paid)

Who did what, and when: settings changes, roster edits, attendance, every signup, members joining and leaving, and what the bot did with its permissions (roles, nicknames, channels, threads and role posts), grouped by the permission each needs. Filter by group, member and period, or Download CSV. Each background run that posts, edits or removes role posts records one entry, naming the member whose changes asked for it when known. A run that changes nothing records nothing. Purchases are recorded on every plan, ready to read if Paid returns; this does not enable the audit screen or admin-channel copies without Paid. Entries are kept for the retention period. If someone asks the bot to delete or redact their data, their actions as an organizer or admin stay, shown as <redacted upon request #0042>; for 72 hours a line in the log says who made the request.
